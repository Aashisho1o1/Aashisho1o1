RipplX, an AI research assistant for SEC filings

RipplX reads a company's 10-K and other SEC filings against the prior period and writes a short brief of what materially changed, the reading an analyst or investor would otherwise repeat every filing season. It also watches for shifts in tone in the risk sections and for patterns such as revenue growing faster than the cash coming in.

Model
Chooses which findings matter, writes the headline, and judges importance.
Code
Checks that each quote exists at the exact filing, section, and character offset, and that every number matches what the company filed in XBRL. The model never does arithmetic.
On failure
A bad finding is dropped on its own. A provider error or missing coverage holds back the whole brief.

An optional skeptic model can object to a finding but can never approve one. I built it that way because someone putting money behind a conclusion should be able to see where it came from, and a confident wrong sentence costs more than a missing one. The checks prove the quotes and the numbers, not that the model read them correctly, so every result in the alpha also gets a human review.

Next: brokerage connections, starting with Robinhood, so an investor sees how a filing change bears on the holdings they already own.

Hazard Proximity, an MCP server

When a wildfire is burning, the first questions are simple. Which hospitals are close to it? Which schools might need to close? This server lets an assistant such as Claude Desktop answer them in plain English from public data, closest first, with phone numbers. There is no language model inside the server. The assistant writes the filter, and plain TypeScript checks it against the live layer schema before anything reaches ArcGIS.

assistant calls  find_nearby(dataset: "hospitals", where: "TRAUMMA = 'LEVEL I'")
server returns   Unknown field 'TRAUMMA'. Did you mean 'TRAUMA'?
assistant retries where: "TRAUMA LIKE 'LEVEL I%'"  sorted list returned

Testing against the live hospital layer turned up a quieter problem. The trauma field is free text, and Level I alone is written 16 different ways. An exact filter found 98 open Level I hospitals and silently missed 142. Nothing errors, the list is just shorter. So the server now hands the model every value of a coded field and tells it to match every spelling.

Chess Coach

A coaching service where Stockfish decides what is true and the language model decides only how to say it. The engine's analysis becomes a fixed set of facts about each move, Claude turns those facts into an explanation, and a verifier checks the explanation against the facts. If it fails, a plain template takes its place.

Most of the real work was in the engine's numbers. Scores are converted to White's point of view once, at the boundary. Mate scores sit on the same scale as material instead of being treated as material. A checkmate on the board is reported as the end of the game, not as a blunder. And because a famous move from Morphy's Opera Game is flagged as a blunder at depth 12 but not at depth 16, quick shallow searches are for responsiveness, and the coach waits for deeper search before calling a move a mistake.

Traume, a trauma-informed support chatbot

A prototype for people in emotional distress, where a careless sentence does real harm. Deterministic crisis checks run before the model is called, and a crisis gets emergency resources immediately. The model works under a prompt that rules out victim blaming, minimizing, and legal or medical directives. Its reply then passes a second set of rules and an optional review, and anything unsafe or unreadable is replaced with a safe fallback.

Conversations are not stored on the server, and there are no cookies or analytics. An adversarial test suite covers victim blaming, overpromised confidentiality, suggestions to contact an abuser, and crisis false positives and negatives, and the run fails if the rule-based layer drops below 90 percent.

OwenWrites, an AI writing platform

A writing platform that helps novelists keep each character's voice consistent across a full manuscript, with OpenAI, Gemini, and locally run models behind one interface so a writer can move a draft between them.

The manuscript is split into passages and indexed in a vector database, so when a writer asks how a character has spoken before, the answer is drawn from their own pages rather than from the model's guess.
